# Dashboard sign-in error review

The screenshot and console trace show that sign-in succeeds and the `/dashboard` route fails while rendering `ServiceSalesCharts`. The chart reads `sales.by_week`, where `sales` is supplied from `data.service_sales`; that response member is undefined in the deployed page's runtime data. The recovery screen's reference is generated by the client route error handler, not by Laravel.

The checked-out Reporting `DashboardSummaryService` includes `service_sales` in successful responses, while the production dashboard asset hash differs from the local build. This establishes a frontend/API contract mismatch at runtime. A mixed or stale deployment is the leading explanation, but the production dashboard JSON and deployed PHP revision were not available, so the exact deployment fault is unconfirmed. The authenticated `GET /api/v1/reports/dashboard` response and deployed revisions are needed to identify it. No application code or data was changed.
