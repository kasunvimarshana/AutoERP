# Production dashboard render incident diagnosis

The production site at `autoerp.tapromall.com` was opened with the user-provided tenant administrator account on 2026-11-12. Sign-in navigated to `/dashboard`, where the React Router recovery page appeared. The browser console reported `TypeError: Cannot read properties of undefined (reading 'by_week')` in the deployed DashboardPage bundle. This is a client render error, so the page's generated reference is logged to the browser console and is not a Laravel log correlation ID.

The current frontend passes `data.service_sales` to `ServiceSalesCharts`, which immediately reads `sales.by_week`. The current Reporting-owned `DashboardSummaryService` always includes `service_sales` in a successful dashboard response. Therefore the production response and frontend bundle are out of contract. A partially deployed or stale backend is the leading explanation, but the authenticated production dashboard JSON body and deployed source revision were not available to verify the precise deployment mismatch.

Recovery: inspect the authenticated `GET /api/v1/reports/dashboard` response in browser DevTools and check whether `data.service_sales` exists. Compare the deployed Reporting service and `ServiceSalesDashboardService` with the frontend build's source revision. Deploy one verified matching application release, regenerate Composer autoload and Laravel caches as required by the deployment process, and smoke-test dashboard sign-in and the API response. Do not hide a missing required backend field with an empty frontend fallback. No source code, production files, schema, or data were changed during this investigation.
